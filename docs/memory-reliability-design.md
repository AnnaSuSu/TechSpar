# 会话记忆失败重试：精简方案

PR 标题：`fix(memory): retry failed memory projection without duplicating profile updates`

## 问题

`ProfileService.afterReview` 先更新 profile.json 中的统计、掌握度、薄弱点和 SM-2，
再写入向量记忆。原实现吞掉 Embedding/SQLite 错误，且命中 session_extractions
后立即返回，导致画像已更新、记忆缺失的会话无法通过重试补齐。
删除提取缓存会重复更新画像，因此不能作为修复办法。

## 实现

1. 在同一次画像文件更新中，保存业务变更、提取缓存与
   `_pending_memory[sessionId]`。待处理快照包含记忆条目及原始时间。
2. 命中提取缓存时只执行待处理投影；在文件仓库更新锁内再次检查缓存，
   避免同一仓库实例中的并发请求重复更新画像。
3. 验证 Embedding 返回数量、维度一致性及有限数值。失败保留待处理快照并抛错。
4. SQLite 在一个事务中删除并重写当前用户、当前会话的
   session_summary / insight / weak_point，不改其他会话或文档条目。
5. SQLite 成功后才清除待处理快照。若这次文件更新失败，
   下次重试再次替换相同会话的条目，因此不会追加重复记忆。
6. 待处理会话的提取缓存不受原 100 条上限淘汰；成功恢复后移入最近完成缓存。
   正常完成的缓存仍保留最近 100 条。
7. 投影错误沿现有调用链设置 `profile_extract_failed`。
   已保存复盘的重试任务使用内部 `profile_only` 标记，
   跳过复盘生成，在 resume、topic_drill、jd_prep、recording 四种模式中复用。
8. 历史页面显示“重试同步”。公开画像响应隐藏内部快照；
   便携归档合并时保留快照及其匹配的提取结果，避免通用数组合并破坏快照。

## 故障演示与验证

运行：

```bash
bun test tests-ts/profile-memory-retry.test.ts
bun run check
```

测试使用临时画像文件、真实 SQLite，以及可控的 AI/Embedding 替身，
无需 API Key 或付费模型。可读的核心断言是：

| 阶段 | 画像累计会话数 | 当前会话记忆条数 | 待处理快照 |
| --- | --- | --- | --- |
| 投影失败后 | 1 | 0 | 保留 |
| 新服务实例重试成功后 | 1 | 3 | 清除 |
| 再次重试后 | 1 | 3 | 不存在 |

其中三条记忆来自测试样本的摘要、洞察和一个薄弱点。
回归测试同时比较 stats、topic_mastery、weak_points，
确认 SM-2 状态不变，并确认未再次调用提取模型。

另外覆盖：向量已提交但确认失败、事务中途写入失败回滚、
用户/会话隔离、无记忆的提取、超过缓存上限、归档合并，以及
四种模式通过真实 HTTP 路由排队并运行同步重试任务。
HTTP 测试确认未鉴权请求被拒绝、复盘文本与逐题评分保留。

## 兼容性与边界

- 无新数据库表、列或公开 API 参数；旧画像文件无需迁移。
- 沿用现有手动重试入口，不新增后台扫描或自动补偿任务。
- 旧版本已吞掉且未标记的失败不会自动被识别或回填。
- 进程在写入会话失败标记之前退出时，可能没有 UI 重试入口；
  本改动不提供完整的进程崩溃后任务恢复。
- 已成功完成且被 100 条缓存淘汰的会话，不提供永久重放去重保证。
- 待处理快照保留到成功重试；持续失败而不重试会增加画像文件大小。
- 跨会话模式归纳仍沿用原来的尽力而为逻辑，不在此投影重试范围。
- 并发保护依赖现有文件仓库的进程内锁，不宣称支持多进程同时修改同一画像。
