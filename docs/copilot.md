# 面试 Copilot

`面试 Copilot` 不是“再来一轮模拟面试”，而是一个两阶段工具：

1. 先做 **Prep Phase**，围绕目标 JD、公司、简历和已有画像生成准备结果。
2. 再进入 **Realtime Phase**，在真实面试或模拟场景里接收实时辅助。

### 适合什么时候用

* 你已经拿到明确岗位 JD，不再是泛练。
* 你想先知道 HR 或面试官大概率会怎么追问。
* 你面试前想把高危路径先暴露出来，而不是现场才踩坑。

### 正确流程

1. 在桌面端进入左侧导航的 **面试 Copilot**。网页端点击该入口会直接显示桌面端下载页。
2. 填公司、岗位，并粘贴完整 JD。
3. 如果你已经上传过简历，系统会自动联动简历做匹配分析。
4. 如果你已经有训练画像，系统也会把领域掌握度和弱点带进准备阶段。
5. 点击开始准备，等待后台完成预处理。
6. 查看结果页里的公司情报、匹配亮点 / 差距、高危路径和策略树线索。
7. 准备完成后，点击 **开始面试辅助** 进入实时模式。
8. 选择你的麦克风，点击 **开始双路采集**，允许系统音频共享和麦克风访问。
9. 说一句话并让会议播放声音，确认“自己”和“对方”两路音量都有反馈。结束时停止采集或退出实时页面。

模型、实时语音识别和联网公司搜索的账号配置见 [外部服务配置](external-services.md)。这些设置按用户保存。

### 推荐云服务配置

- 部署方在私有 `.env` 中填写 `COPILOT_LLM_API_KEY`，默认使用 DeepSeek 官方地址 `https://api.deepseek.com` 和 `deepseek-flash`；可通过 `COPILOT_LLM_API_BASE`、`COPILOT_LLM_MODEL` 指定地址和模型。该配置只用于 Copilot，不替换训练、复盘等功能的 LLM。
- Copilot 实时建议使用非思考流式输出，最多生成 600 tokens，先给核心结论。准备阶段的结构化分析仍使用原有思考配置。
- 实时语音独立读取 `COPILOT_DASHSCOPE_API_KEY` 和 `COPILOT_DASHSCOPE_WORKSPACE_ID`，不修改录音复盘的转写配置。实时模型为 `qwen-audio-3.1-asr-flash-streaming`；业务空间 ID 留空时使用北京公共入口。社区版未配置专用服务时，沿用用户设置中的 LLM 和 DashScope 配置。
- 桌面端将系统音频与麦克风分别送入两个识别会话。字幕会随识别修正，最终句子才触发回答；新问题会取消尚未完成的上一题回答。
- `qwen-audio-3.1-asr-flash` / `filetrans` 是整段录音接口，不能替代实时流式输入。开启 HTTP SSE 也不会把它变成麦克风实时接口。

### 你会得到什么

* **公司情报**：帮助你回答时更贴近目标公司语境。
* **JD 拆解**：看岗位真正看重哪些技术点和能力维度。
* **匹配亮点 / 差距**：哪些经历能放大，哪些短板要先补。
* **高危路径**：哪些追问一旦打到，你最容易失分。
* **实时建议**：进入实时模式后，系统会根据当前问题给回答方向和风险提示。

### 使用建议

* 不要只贴岗位标题，至少保留职责、要求、加分项和技术栈。
* 简历、画像都不是强制前置条件，但补全后结果会更像真实面试。
* Copilot 的价值不在“替你答题”，而在提前暴露追问路径和回答风险。
* 如果预处理结果已经指出明显差距，先回题库、专项训练或 JD 备面补一轮，再回来用 Copilot。


### 桌面音频

- 麦克风对应“自己”，系统音频对应“对方”；两路独立转写，不混音，不调用声纹服务。
- 音频通过当前服务端发送给转写服务，服务端密钥不会下发到客户端。
- 建议佩戴耳机，关闭音乐、通知等无关声音。系统音频捕获的是电脑输出，不能自动隔离某个会议参与者。
- 首次使用 macOS 需要允许麦克风及系统音频录制。权限窗口里若出现屏幕选择，是系统采集接口要求；屏幕画面不会发送给后端。
- 拒绝授权、共享结束、设备断开或网络断线时会停止本机两路采集。重连后需手动重新开始。
- 没有检测到声音时显示“尚未检测到声音”，不能据此认定权限正常；请播放会议声音并检查系统授权。
- 旧的声纹设置入口已移除。已有声纹数据和兼容接口暂时保留，但不会参与新的 Copilot 会话。

### 实现与参考

参考 [Meetily v0.4.1](https://github.com/Zackriya-Solutions/meetily/tree/a2cb62e827da7ef59f65064c97233efb2313878e)
的音频监测与生命周期设计，移植了音量计算；采集由 Electron 原生接口完成。
[来源和许可](third-party/meetily.md)。没有引入其 Rust/Tauri 运行时或混音流程。

桌面客户端以 `start.audio_mode=dual` 协商双路协议。二进制帧头为
`0x54 0x53 0x01 source`（0=系统音频，1=麦克风），后续是 16 kHz 单声道
PCM16 little-endian。每路使用独立 ASR 会话，角色由来源确定。
未协商双路的旧客户端仍可发送原始 PCM，但不再使用声纹识别。
