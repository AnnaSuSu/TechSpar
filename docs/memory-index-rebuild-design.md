# 保留并重建会话记忆

PR 标题：`fix(memory): preserve session memories across embedding changes and index rebuilds`

## 问题

保存新的 Embedding 模型或手动重建索引时，`KnowledgeIndexService.invalidateUser`
原先删除当前用户的全部 `memory_vectors`。重建只处理画像薄弱点、个人文档和知识库，
没有重建 `session_summary` / `insight`，因此重建成功后仍然缺少历史会话检索。
同时，个人文档的向量被删除，但文档仍显示 `ready` 和旧分块数。

最近的提取缓存可能仍保留摘要，待处理快照也可能保留正文；但现有索引重建不会
使用它们，已完成会话的投影重试也不会重建被删除的向量。本文修复继续保留的
会话记忆，不承诺恢复旧版本已删除的数据。

## 实现

1. 在同一个 SQLite 事务内，保留当前用户的摘要和洞察行，通过现有 `metadata`
   标记向量失效；清理其他派生向量和题目向量缓存，并把个人文档标为
   `needs_reindex`，分块数清零。数据库没有个人文档表时也可正常失效。
   先完成失效再保存新模型，失效失败时继续使用原来的 provider 配置。
2. `listProfileMemories` 跳过失效行，防止同维度模型切换后误用旧向量。
   失效标记写入数据库，服务重启后仍生效。
3. 重建流程新增“历史会话记忆”步骤。读取保留的正文，按会话调用 Embedding，
   验证数量、非空维度、同批维度一致性和有限数值。旧行没有会话 ID 时逐行处理。
4. 每个会话在单独事务内原位更新向量并移除失效标记，不删除重插，保留行 ID、
   正文、主题、会话归属、其他元数据和原始时间。重建不重跑画像提取，不改变
   统计、掌握度和 SM-2。
5. 每次失效使用不同标记。更新时比较读取时的元数据版本，若期间再次失效或
   原行被替换/删除，整批回滚并报告重试，避免旧重建重新启用失效向量。
6. Embedding 或 SQLite 失败时保留正文，可以再次重建。清理阶段失败则终止，
   返回明确的 fatal 事件；其他步骤继续沿用原来的逐步报错语义。
7. SSE 完成事件增加 `rebuilt.session_memories`，同步更新契约、生成文件与 fixture。
   设置页显示步骤失败，避免随后收到 done 就显示“已重建”；更新保留正文的提示。

使用原位更新代替删除再插入，是为了只更新派生的 embedding，同时保持来源、
时间与行身份不变，并能拒绝失效版本的写入。不新增数据库表或列。

## 验收

测试样本每个会话包含一个摘要、一条洞察和一个薄弱点，N 为该样本的会话数。
其他合法提取可能没有摘要，生产环境不要求固定 2N 行。

| 阶段 | 摘要 + 洞察行数 | 历史语义检索 | 个人文档状态 |
| --- | --- | --- | --- |
| 切换前 | 2N | 命中 | `ready` |
| 切换后、重建前 | 2N，失效 | 空 | `needs_reindex`，0 分块 |
| 成功重建后 | 2N，新向量，正文与原始时间不变 | 恢复 | `ready` |
| 记忆步骤失败后 | 2N，失败会话仍失效 | 不使用失败会话的旧向量 | 由文档重建步骤决定 |
| 再次重建成功后 | 2N，无重复行 | 恢复 | `ready` |

运行，不需要 API Key：

```bash
bun test tests-ts/memory-index-rebuild.test.ts
bun run gen:api
bun run check
```

17 个定向用例使用临时文件、真实 SQLite、真实画像和个人文档仓库，通过 Hono
`app.request()` 触发 SSE。覆盖同维度/不同维度切换、手动和重复重建、用户隔离、
服务重启后的失效状态、缺少会话 ID、无历史数据、异常 Embedding、SQLite 事务
回滚、并发再次失效、删除后的写入、取消和鉴权。

## 边界

- 只修复 Embedding 设置变化与手动索引重建；个人归档导入仍由后续 PR 处理。
- 继续沿用现有模型变化判定；完整模型签名、同名模型更换 API 地址和维度身份
  属于 PR-2，本改动的失效标记不能检测未经过失效流程的向量空间变化。
- 保留摘要/洞察正文；`weak_point` 仍由画像重建，三种写入路径的统一不在此 PR。
- 保持逐步骤、逐会话提交语义。失败前已完成的会话可以检索，失败会话保持失效；
  再次重建会重新处理保留的全部正文。
- 完成事件的 `last_rebuild_at` 延续已有的尝试结束时间语义，不代表所有步骤成功；
  调用方应检查步骤错误与 `rebuilt` 标志。新增字段需要客户端与服务端配套升级。
